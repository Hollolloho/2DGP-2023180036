# 2D 게임 프로그래밍 120분 시험 정리본 설계

작성일: 2026-10-20

## 1. 목적과 승인된 방향

사용자가 지정한 `Slides` 폴더의 PPTX, HTML, PDF를 강의 번호 순서로 정리한다. 핵심 내용을 약 120분 동안 공부할 수 있는 한국어 HTML 문서를 만든다. 사용자는 2026-10-20 대화에서 단일 HTML 교재형 구성을 승인했고, 파이썬 코드와 게임의 정의는 반드시 출제된다고 추가로 알려주었다.

완성 파일은 `2DGP-2023180036/시험정리_2시간.html`이다. 브라우저에서 파일을 더블클릭해 연다. 서버 실행, 패키지 설치, 인터넷 연결이 필요하지 않다.

120분은 권장 학습 시간의 합계다. 모든 사용자의 실제 소요 시간을 보장한다는 뜻은 아니다.

## 3. 출제 우선순위와 필수 내용

`출제 확정 · 사용자 확인` 표시는 파이썬 코드와 게임의 정의에 적용한다. 실제 시험지를 확인했다는 뜻으로 표현하지 않는다. 나머지 지정 항목에는 `사용자 출제 메모`를 표시한다. 제작한 문제는 복습 문제이며 실제 기출문제로 부르지 않는다.

### 파이썬과 코드

- 기본 자료형, `input()`과 형 변환, 연산자, 인덱스와 슬라이스, 리스트·튜플·딕셔너리·집합
- `if`/`elif`/`else`, `while`, `for`, `range()`, 함수의 정의·호출·반환, 지역·전역 변수
- 리스트 컴프리헨션: `[표현식 for 변수 in 반복대상]`, 조건을 붙인 형태, 같은 일을 하는 반복문과 결과 비교
- 클래스·인스턴스·속성·메서드·`self`·`__init__`
- 코드를 읽고 실행 순서, 상태 변화, 출력 결과를 설명하는 연습
- 반복문과 조건문, 프레임 계산, 키 입력 처리, 좌표 변환을 빈칸으로 복습

### 게임의 정의와 기초

- 게임: 가상 월드의 객체 간 상호작용을 시뮬레이션하고 결과를 화면에 보여주는 프로그램이라는 강의 설명
- 2D 게임: 위치와 움직임을 평면의 x, y 좌표로 표현하고 현재 상태를 2D 이미지의 조합으로 보여주는 게임이라는 강의 설명
- 배경/월드와 캐릭터/오브젝트의 역할
- 캔버스의 왼쪽 아래가 `(0, 0)`, 오른쪽으로 x 증가, 위쪽으로 y 증가한다는 점을 최우선 강조
- 좌표계 설명은 pico2d 캔버스 기준으로 한정하며 Turtle·윈도우 입력 좌표와 구별
- 이미지 로드와 출력, 중앙 기준 이미지 배치, `clear_canvas()`와 `update_canvas()`
- 게임 로직은 객체 상태 계산, 게임 렌더링은 계산된 상태를 그리는 단계
- 입력 처리 → 상태 갱신 → 화면 출력의 반복과 화면 갱신의 역할

### 개발 절차·애니메이션·입력

- 저장/커밋/push/제출의 위치와 의미, 특히 커밋은 내 PC의 Git 저장소에 변경 이력을 기록한다는 점
- `PRD.md`의 역할과 요구사항 → 구현 → 실행 검증의 연결
- Sprite, Sprite Sheet, Action, Frame의 정의와 구별
- `clip_draw(left, bottom, width, height, x, y)`의 인자 의미, 원본 이미지 영역과 화면 출력 좌표의 차이
- 균일 프레임의 `frame * FRAME_WIDTH`, `action * FRAME_HEIGHT`, `(frame + 1) % frame_count`
- `dir > 0`이면 `RUN_RIGHT`, `dir < 0`이면 `RUN_LEFT`, 나머지는 `IDLE`
- `get_events()`, `event.type`, `event.key`, KEYDOWN/KEYUP, 종료 이벤트
- `canvas_y = canvas_height - 1 - event.y`의 이유와 위쪽/아래쪽 경계 계산

### 객체와 추상화 보충

- 추상화: 필요한 상태와 동작을 골라 모델로 표현한다는 설명
- 게임 객체: 게임 월드를 구성하는 요소라는 사용자 메모를 설명
- Grass 예제의 초기화·그리기·갱신 역할을 구분
- 사용자의 `def init(self)`는 `def __init__(self)`로 수정하고 그 이유를 설명
- `self.image = load_image('grass.png')`, `self.image.draw(400, 30)`, `update()`의 `pass`를 각각 설명
- Grass 원문과 추상화 원문은 검색한 강의 자료와 소스에서 확인되지 않았으므로 사용자 메모를 바탕으로 한 보충 설명으로 표시

## 4. 120분 학습 구성

| 순서 | 학습 범위 | 권장 시간 |

각 강의는 핵심 설명 → 기억할 문장/코드 → 흔한 혼동 → 짧은 복습 문제 순서로 구성한다. 파이썬과 게임 정의를 요약만 하고 넘기지 않는다. 파이썬 코드는 이후 게임·애니메이션·입력 단원에서도 계속 연결한다. 상세한 설치 절차, 교수자 연락처, 이미 반복 설명한 내용은 학습 시간을 줄이기 위해 압축한다.

## 5. HTML 구성과 동작

- 문서 상단: 사용 방법, 120분 학습 순서, 출제 우선순위
- 강의 번호 순서의 목차와 이동 링크
- 본문 검색: 검색어와 일치하는 학습 항목을 찾고 검색 결과가 없을 때 안내
- 코드 블록은 공백과 들여쓰기를 유지하고, 좁은 화면에서는 가로 스크롤 허용
- 정답은 HTML `details`/`summary`를 이용해 펼쳐 확인
- 글자와 배경의 대비, 명확한 키보드 포커스, 입력 필드의 이름을 제공
- 인쇄 시 조작 UI를 숨기고 복습 정답을 포함해 읽기 좋은 형태로 출력
- JavaScript를 사용할 수 없어도 본문과 목차, 기본 정답 펼치기는 동작
- CSS, JavaScript, 본문 데이터는 HTML 안에 포함하고 외부 폰트·CDN·이미지·네트워크 요청을 사용하지 않음

자료 제목과 강의/페이지/슬라이드 위치를 사람이 읽을 수 있게 표시한다. 원본 링크는 보조 기능이며, 링크를 열지 않아도 공부를 마칠 수 있다. 타이머, 계정, 서버, 웹 호스팅, 온라인 코드 실행기는 만들지 않는다.

## 6. 자료 간 차이 처리

- 입력 처리 HTML 내부 제목은 LEC09로 쓰인 곳이 있지만 파일과 PDF를 기준으로 LEC10에 배치한다.
- LEC09 강의 HTML의 실습 진행 설명에 나오는 `1200×600`, 현재 PRD와 소스의 `1200×800`은 각각의 버전과 출처를 구별한다. 특정 실습의 창 크기를 모든 게임에 적용되는 상수처럼 암기시키지 않는다.
- 프레임 개수 등 실습 버전마다 달라진 수치는 원본을 대조해 설명한다. 일반적으로 외울 내용은 프레임 좌표와 순환 원리다.
- 출제 메모와 원본에서 확인한 내용, 추가 학습 예제를 구분해 출처를 과장하지 않는다.

## 7. 검증과 완료 기준

1. 기본 자료 12개의 내용이 강의별로 검토되고 필요한 내용이 반영되어 있다.
2. 사용자 출제 메모의 모든 항목이 본문 또는 보충 절에 있으며 목차에서 찾을 수 있다.
3. 권장 시간이 정확히 120분이고 존재하는 강의 번호 순서를 따른다.
4. 게임의 정의와 파이썬 코드를 우선 학습할 수 있으며 설명·코드 해석·복습이 모두 있다.
5. HTML을 로컬 브라우저에서 열어 목차, 검색, 정답 펼치기, 인쇄 레이아웃을 확인한다.
6. 넓은 화면과 좁은 화면에서 본문·표·코드가 잘리거나 겹치지 않는다.
7. 외부 리소스 없이 열리고 필요한 설명이 파일 안에 모두 있다.
8. Python 예제의 문법과 제시한 결과를 검사한다. 그래픽 예제는 pico2d 실행 환경과 리소스가 필요한 예제임을 구별하고, 좌표·프레임·방향 계산은 별도로 검산한다.
9. 설치나 배포 없이 완성 HTML의 로컬 경로와 여는 방법을 안내한다.

## 8. 후속 절차의 제약

요청된 brainstorming 스킬에 따라 이 설계 문서를 사용자에게 검토받는다. 후속 절차에서 요구하는 `writing-plans` 스킬은 설치된 스킬 목록과 로컬 검색에서 찾지 못했다. 스킬을 임의로 설치하거나 실행했다고 주장하지 않는다. 설계 검토 후, 수동 구현 계획으로 대체하는 방법에 대한 사용자 지시를 확인하고 진행한다.
