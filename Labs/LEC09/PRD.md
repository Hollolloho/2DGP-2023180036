# Sonic 애니메이션 뷰어 PRD

## 1. 문서 목적

`Labs/LEC09/sonic-sprite.png`에 들어 있는 Sonic 스프라이트를 pico2d로 재생하는 학습용 애니메이션 뷰어를 개발한다.

사용자는 프로그램을 실행한 뒤 별도의 설정 없이 스프라이트 시트의 동작을 순서대로 확인할 수 있어야 한다. 이 문서는 구현 범위, 재생 규칙, 화면 기준, 테스트 기준을 정의한다.

## 2. 제품 정의

| 항목              | 내용                                                |
| ----------------- | --------------------------------------------------- |
| 제품명            | Sonic Animation Viewer                              |
| 실행 파일         | `sonic_animation_viewer.py`                       |
| 실행 폴더         | `Labs/LEC09`                                      |
| 입력 이미지       | `sonic-sprite.png`                                |
| 대상 사용자       | 게임 개발 학습자 및 스프라이트 확인이 필요한 개발자 |
| 그래픽 라이브러리 | `pico2d`                                          |
| 프로그램 형태     | 단일 Python 파일                                    |

## 3. 목표와 성공 기준

프로그램을 실행하면 `sonic-sprite.png`를 읽고 Sonic을 화면 중앙에 표시한다. 각 동작은 20 FPS로 재생되고 동작마다 5회 반복된다. 한 동작이 끝나면 1초 동안 마지막 프레임을 유지한 뒤 다음 동작으로 넘어간다. 마지막 동작이 끝나면 첫 동작부터 다시 재생한다.

성공 기준은 다음과 같다.

- 이미지가 정상적으로 로드된다.
- 스프라이트 시트에 정의된 모든 동작이 누락 없이 재생된다.
- 모든 동작이 정해진 순서로 반복된다.
- 프레임 간격, 반복 횟수, 동작 사이 대기 시간이 요구값과 일치한다.
- 캐릭터가 지정된 화면 중심과 표시 영역 안에 그려진다.
- 창 닫기 또는 `ESC` 입력으로 오류 없이 종료된다.

## 4. 범위

### 4.1 포함 기능

1. 실행 파일 기준으로 `sonic-sprite.png`를 찾고 로드한다.
2. 스프라이트 시트의 동작별 프레임 영역을 정의한다.
3. 현재 동작의 프레임을 정해진 순서로 표시한다.
4. 현재 동작을 정확히 5회 반복한다.
5. 동작 사이에 1초 대기한다.
6. 모든 동작을 순서대로 재생한 뒤 처음부터 순환한다.
7. 캐릭터를 화면 중앙에 표시하고 지정된 영역에 맞춰 확대한다.
8. 창 닫기와 `ESC` 키 입력을 처리한다.

### 4.2 제외 기능

- 스프라이트 시트 편집, 자르기, 저장, 내보내기
- 사용자가 애니메이션 순서나 속도를 변경하는 UI
- 캐릭터 이동, 점프, 충돌, 점수 등 게임 플레이 기능
- 사운드와 배경 음악
- 여러 소스 파일 또는 별도 애니메이션 프레임워크 사용

## 5. 화면 및 표시 기준

### 5.1 캔버스

- 캔버스 크기: `1200 x 800`
- 캐릭터 표시 중심: `(600, 400)`
- 배경: 프레임을 확인하기 쉬운 단색

### 5.2 캐릭터 표시 영역

캐릭터는 다음 사각형 안에 들어오도록 표시한다.

```text
minX = 400
maxX = 800
minY = 200
maxY = 600
```

표시 영역의 크기는 `400 x 400`이다. 프레임의 가로세로 비율은 유지하고 이 영역을 넘지 않는 최대 크기로 확대한다. 원본 프레임이 이미 영역보다 크면 영역 안에 맞게 축소한다.

`(600, 400)`은 스프라이트 시트의 원본 좌표가 아니라 캔버스에서 캐릭터를 표시할 중심 좌표다.

## 6. 애니메이션 데이터 정의

각 동작은 다음 정보로 정의한다.

| 필드        | 설명                                    |
| ----------- | --------------------------------------- |
| 이름        | 동작을 식별하는 이름                    |
| 시작 좌표   | 스프라이트 시트 안에서 첫 프레임의 위치 |
| 프레임 크기 | 한 프레임의 가로·세로 크기             |
| 프레임 수   | 해당 동작에 포함된 이미지 프레임 개수   |
| 순서        | 전체 재생에서의 동작 순서               |

스프라이트 시트의 실제 배치를 확인한 뒤 동작 목록과 좌표를 확정한다. 빈 셀이나 배경만 있는 셀은 프레임에 포함하지 않는다. 동작마다 프레임 수가 달라도 같은 재생 로직으로 처리한다.

## 7. 재생 규칙

- 프레임 간격: `0.05초`
- 재생 속도: 초당 20프레임(`20 FPS`)
- 동작별 반복 횟수: `5회`
- 동작 전환 대기: `1초`
- 대기 중 표시: 이전 동작의 마지막 프레임 유지
- 전체 동작 종료 후: 첫 동작의 첫 프레임으로 순환

동작 하나의 재생 순서는 다음과 같다.

1. 현재 동작의 첫 프레임을 표시한다.
2. 0.05초마다 다음 프레임으로 이동한다.
3. 마지막 프레임 다음에는 첫 프레임으로 돌아가 반복 횟수를 1 증가시킨다.
4. 반복 횟수가 5가 되면 마지막 프레임을 유지하며 1초 대기한다.
5. 다음 동작의 첫 프레임으로 전환한다.

## 8. 프로그램 상태

프로그램은 다음 상태를 사용한다.

| 상태                      | 설명                    | 전환 조건           |
| ------------------------- | ----------------------- | ------------------- |
| `PLAYING`               | 현재 동작의 프레임 재생 | 동작 5회 완료       |
| `PAUSE_BETWEEN_ACTIONS` | 동작 전환 전 1초 대기   | 1초 경과            |
| `STOPPING`              | 종료 요청을 받은 상태   | 캔버스 정리 후 종료 |

필수로 관리할 값은 다음과 같다.

- 현재 동작 인덱스
- 현재 프레임 인덱스
- 현재 동작의 반복 횟수
- 다음 프레임 전환 또는 대기 종료까지의 시간
- 종료 요청 여부

## 9. 실행 및 종료 흐름

### 9.1 시작 흐름

1. 실행 파일의 위치를 기준으로 이미지 경로를 계산한다.
2. `sonic-sprite.png`의 존재 여부를 확인한다.
3. 동작 목록과 프레임 정의가 비어 있지 않은지 확인한다.
4. pico2d의 `1200 x 800` 캔버스를 연다.
5. 캔버스가 열린 뒤 이미지를 한 번 로드한다.
6. 첫 동작의 첫 프레임부터 재생한다.

### 9.2 종료 흐름

- 창 닫기 이벤트 또는 `ESC` 키를 받으면 종료 요청을 설정한다.
- 종료 요청 후 새 프레임을 재생하지 않는다.
- `close_canvas()`를 호출하고 프로그램을 종료한다.

## 10. 오류 처리

| 상황                               | 처리 방법                                     |
| ---------------------------------- | --------------------------------------------- |
| 이미지 파일 없음                   | 파일 경로를 포함한 오류를 출력하고 종료       |
| 이미지 로드 실패                   | 예외 내용을 출력하고 캔버스를 정리한 뒤 종료  |
| 동작 목록이 비어 있음              | 애니메이션을 시작하지 않고 원인을 출력        |
| 프레임 좌표가 이미지 범위를 벗어남 | 해당 정의를 수정할 수 있도록 오류 내용을 출력 |
| 알 수 없는 입력 이벤트             | 무시하고 다음 프레임 진행                     |
| 종료 중 예외 발생                  | 가능한 범위에서 캔버스를 닫고 오류를 출력     |

파일 존재 여부와 프레임 정의 검증은 캔버스를 열기 전에 수행한다. pico2d 이미지는 캔버스가 열린 뒤 한 번만 로드하며, 매 프레임 이미지 파일을 다시 읽지 않는다.

## 11. 기술 제약

- Python 3와 `pico2d`를 사용한다.
- 소스 코드는 `sonic_animation_viewer.py` 하나로 작성한다.
- 입력 이미지는 같은 폴더의 `sonic-sprite.png` 하나만 사용한다.
- 별도의 외부 패키지, 웹 브라우저, 네트워크 연결을 사용하지 않는다.
- 프레임 출력은 pico2d의 `clip_draw()` 규칙과 좌표계를 따른다.
- 화면 갱신은 매 프레임 `clear_canvas()`, 그리기, `update_canvas()` 순서로 처리한다.
- 이미지 경로는 현재 작업 폴더가 아니라 실행 파일 위치를 기준으로 처리한다.
